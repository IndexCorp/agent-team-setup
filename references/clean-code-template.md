# Шаблон секции «Чистый код» для AGENTS.md

Впиши в AGENTS.md (после секции «Качество и общие запреты» или слей с ней).
Заполнить под выбранные стеки: инструменты из скобок — примеры, выбрать
реальные и указать команды запуска. Каждый пункт должен быть проверяемым
«да/нет», иначе агенты его игнорируют.

```markdown
## Чистый код (критично)

1. **Без дубликатов.** Перед написанием — поиск по своей зоне готового
   ({{ZONE_REUSE_EXAMPLES: бекенд — сервисы и схемы; фронтенд — компоненты
   и утилиты; мобильный — экраны и DTO}}). Вторая копия похожего кода —
   вынести в общий модуль своей зоны; дубли между зонами запрещены —
   общее живёт в контракте (доки), а не в скопированном коде.
2. **Линтер и форматтер — часть гейта.** {{LINT_COMMANDS}} проходят перед
   каждым коммитом; предупреждения линтера в новых строках = работа не
   готова. Конфигурацию линтера не ослаблять без владельца.
3. **Типизация там, где стек даёт.** {{TYPING_RULES: TypeScript strict,
   mypy на пакетах приложения, null-safety Kotlin}} — новое кодо без
   типов/с аннотациями-пустышками = находка ревью.
4. **Ошибки обрабатываются на границах.** Сеть, пользовательский ввод,
   парсинг внешних данных: обязательные ветки ошибки и таймаута, понятные
   состояния UI, никакого «поймал и промолчал» (пустой except/catch —
   находка). Пользователь видит осмысленное сообщение, лог — причину.
5. **Функции маленькие, имена честные.** Функция делает одно названное
   дело; имя не требует чтения тела; вложенность < 4 уровней; магические
   числа и строки-флаги — в именованные константы.
6. **Безопасность по умолчанию.** Валидация всего входа на границе
   (allowlist, не blacklist); минимум привилегий; новая зависимость =
   обоснование + зафиксированная версия + известная лицензия; секреты
   только в env вне git; PII и токены не в логах. Детали —
   security-ревью (гейт зоны).
7. **Ничего конфигурируемого в коде (хардкод запрещён).** Значения,
   зависящие от окружения, развёртывания или владельца, живут в
   конфиге/env, код знает только имена: секреты и ключи; URL, домены,
   адреса API; порты; таймауты, лимиты, размеры; пути вне проекта;
   пользовательские тексты и названия. В коде — константы/переменные из
   конфига и её осмысленное имя; дефолт в коде допустим только
   develop-заглушке с явным именем вида `DEFAULT_*`. При переносе проекта
   (новый домен, смена секретов, другой клиент) правится конфиг — не код.
8. **Сложность под контролем.** Дублирующиеся ветвления и «простыни»
   условий — в таблицы/данные/полиморфизм; функция с 6+ ветвлениями —
   кандидат на декомпозицию (цитируется в ревью).
```

## Откуда взяты пункты (для организатора, не в AGENTS.md)

- Пункты 1–2 — стандартная дисциплина индустрии (dry, lint-as-gate),
  подтверждена практикой код-ревью всех крупных проектов.
- Пункт 3 — OWASP/secure-coding и docs экосистем: ошибки типов — источник
  доли runtime-ошибок.
- Пункт 4 — OWASP ASVS (обработка ошибок как контрол безопасности):
  пустые обработчики = скрытые отказы.
- Пункт 6 — принципы secure-by-default из secure-coding гайдлайнов
  (OWASP): безопасный путь = путь наименьшего сопротивления.
- Пункт 8 — классика (Fowler): высокая цикломатическая сложность
  коррелирует с плотностью дефектов.

При споре «это чистота или вкусовщина» решает владелец; конвенция —
не догма, а набор проверяемых правил, с которыми согласен владелец.
