# Шаблон mailbox `docs/mailbox/to-<роль>.md`

```markdown
# Почта: to-{{ROLE}}.md

Это ящик {{ROLE}}-агента — здесь только записи, адресованные ему. Если ты
не {{ROLE}}-агент — не пиши сюда; адресату — в его ящик `to-<роль>.md`.

Формат записи (append-only, чужие записи не удалять; статус меняется
правкой поля):

```
### YYYY-MM-DD · <от кого> · [NEW] Короткая тема
- Что нужно: …
- Контекст/ссылки: <доки/коммиты>
- Критичность: блокер / обычная
- Статус: NEW → TAKEN → DONE / DECLINED (причина)
```

Статусы (полный алфавит, менять только вправо по цепочке):

- `NEW` — задание ждёт владельца ящика.
- `TAKEN` — принято в работу (владелец).
- `NEEDS_CONTEXT` — владельцу нужен ответ/артефакт от отправителя или
  третьего агента: в записи вопрос и кому он адресован. Отправитель
  отвечает правкой статуса обратно в `TAKEN` (+ответ в запись).
- `DONE` — выполнено (владелец указывает коммит с результатом).
- `DONE_WITH_CONCERNS` — выполнено, но с оговоркой: что именно смущает и
  что с этим делать — в записи; отправитель решает (принять → `DONE`,
  переспросить → `NEEDS_CONTEXT`, переделать → `NEW` с пояснением).
- `DECLINED` — отказано с причиной (обязательной).

Тема бага — с префиксом `БАГ:` (файл/эндпоинт, шаги, ожидание vs факт).
Тривиальные изменения, не затрагивающие соседей (правка только своей
зоны, контракт не менялся), письма не требуют — почта не церемония.
Записей со статусом DONE/DECLINED/DONE_WITH_CONCERNS больше ~20 —
перенести в `archive-{{ROLE}}.md`.
```
