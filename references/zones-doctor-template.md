# Шаблоны: zones.yml + pre-commit hook + доктор протокола

Два детерминированных барьера протокола: владение зонами и целостность
структуры. Живут в репо как код проекта (править могут агенты зон, но
изменение семантики — через владельца).

## 1. `zones.yml` — карта владения

```yaml
# Каждая зона: glob-паттерны файлов, которые правит ТОЛЬКО её агент.
# Протокол-файлы (AGENTS.md, HANDOFF.md, docs/mailbox/, check_protocol.py)
# общие — их не вносить в зоны; изменение семантики — через владельца.
zones:
  - role: backend
    paths: ["backend/**", "docs/API.md", "docs/db_schema.md"]
  - role: frontend
    paths: ["frontend/**"]
  - role: admin
    paths: ["admin/**"]
  - role: mobile
    paths: ["mobile/**"]
```

Генерируется организатором из таблицы ролей AGENTS.md. Контрактные доки
(API.md, db_schema.md) — владение бекенда: они часть его зоны, потребители
читают, но не правят.

## 2. Pre-commit hook (`.githooks/pre-commit` + `git config core.hooksPath .githooks`)

Логика хука (bash или python — выбрать по стеку проекта):

1. Список изменённых файлов: `git diff --cached --name-only`.
2. Для каждого файла — найти зоны, чьи glob'ы его покрывают.
3. Файл вне всех зон → ок (общие файлы).
4. Файлы из нескольких зон → FAIL: «атомарный коммит затрагивает зоны:
   X, Y — разделите коммиты или договоритесь через mailbox».
5. Файлы одной зоны → сверить с allowlist текущего агента, если он
   известен среде (env `AGENT_ROLE`); если роль не задана — только
   предупреждение, не блок.

Хук advisory по умолчанию (предупреждает), strict — по решению владельца
(блокирует). Bypass для организатора: `git commit --no-verify` — осознанный
шаг, о котором знает владелец.

## 3. Доктор протокола (`check_protocol.py`, корень репо)

Скрипт-аудит структуры: exit 0 = протокол цел, exit 1 = список проблем.

Проверки:

1. `AGENTS.md` и `HANDOFF.md` существуют и не пусты; в AGENTS.md есть
   таблицы ролей и портов (маркеры: `## Роли`, `## Dev-порты`).
2. Каждая роль из таблицы ролей имеет: `README` зоны (по пути из таблицы),
   mailbox `docs/mailbox/to-<роль>.md`, запись в `zones.yml`.
3. В шапке каждого mailbox есть строка-гвард «Это ящик …» и легенда
   статусов (маркер `NEW → TAKEN`); в README каждой зоны есть секция
   «Грабли» и секция «Критерии готовности» (маркеры заголовков).
4. Каждый гейт из AGENTS.md реально существует: упомянутые скрипты/файлы
   проверяются на наличие (парсер: пути вида `*.py`, `*.md`, команды с
   именами скриптов — эвристика + явный список в докторе).
5. Таблица портов: порты уникальны, у каждого указана зона.
6. `zones.yml` валиден (YAML-парс, каждая зона имеет непустой paths) и
   покрывает все каталоги зон из таблицы.
7. docs-sync-скрипт (если заявлен в гейтах) запускается — doctor вызывает
   его и требует exit 0 или явное «не настроен» в конфиге доктора.
8. `.gitignore` содержит гварды сессионных артефактов (`.zcode/plans/`,
   `.zcode/shots/`).

Вывод: группы `OK` / `PROBLEM` с файлом и что чинить. Скрипт не пишет в
файлы — только читает и сообщает.

## Встраивание

- Команда доктора вписывается в AGENTS.md (правила качества) и в HANDOFF.md
  (раздел «Работа агентов»): «гонять при любом изменении протокола».
- Организатор запускает доктора сразу после генерации артефактов — свежий
  протокол обязан проходить собственные проверки.
- Хук и доктор дополняют, а не заменяют друг друга: хук — про ЧЬИ файлы,
  доктор — про целостность СТРУКТУРЫ протокола.
