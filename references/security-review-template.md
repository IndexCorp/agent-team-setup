# Security Review (проект)

Ревью безопасности незакоммиченного диффа. Ревьюер код не правит —
только отчёт; исправляет агент своей зоны.

## Процедура

Запусти ровно одного общего агента (general-purpose, не в фоне) с промптом:

«Ревью безопасности uncommitted-диффа репозитория <полный путь>.
1. Вычисли дифф (git diff + git status; новые файлы целиком).
2. Пройди чек-лист: по каждому пункту — применим ли и соблюдён ли.
3. Верни вердикт: PASS или FINDINGS списком {файл:строка, severity P0/P1/P2,
   что нарушено, как исправить}. Код не переписывай.»

## Действия по вердикту

- PASS — зафиксировать «security-review: PASS» в итоговом сообщении.
- P0 (эксплуатируемо сейчас) / P1 (риск при злоупотреблении) — чинить до

- P2 (гигиена) — чинить, если дёшево; иначе перечислить владельцу.

## Блоки чек-листа по стекам

**Backend API:**
- SQL/ORM без конкатенации строк; LIKE-паттерны экранированы.
- Валидация ввода на схемах: allowlist-поля, длины, диапазоны; ошибки 4xx, не 500.
- Авторизация на каждом закрытом эндпоинте; IDOR: объекты владельца проверяются.
- Rate-лимиты на публичных и спамогенных маршрутах; вебхуки — по подписи,
  fail-closed.
- Секреты и PII (телефоны, адреса) не в логах и ответах ошибок.
- Миграции идемпотентны; изменение контракта — доки в том же коммите.

**Web UI:**
- Пользовательский контент рендерится как текст: без innerHTML/dangerouslySetInnerHTML/eval.
- Ссылки: http(s) после валидации; javascript:-URL запрещены; внешние — target/rel безопасны.
- Токен сессии не в URL/логах/localStorage; 401 — глобальный сброс сессии.
- Деструктив — confirm-гейт; двойная отправка заблокирована.
- Ошибки сервера (400/409/422) показываются из detail, без автоповторов.

**Mobile:**
- Токены в системном хранилище (Keystore/Keychain), не plain storage.
- Deep-link параметры валидированы по allowlist; переходы не выполняют действий.
- Внешние ссылки — scheme+host allowlist, незнакомое в системный браузер.
- PII/токены не в логах; release-сборка без debug-логов.

**Общее (все стеки):**
- Комментарии в диффе = находка (правило протокола).
- Хардкод конфигурируемого = находка: секреты, URL/домены, порты,
  таймауты/лимиты, внешние пути, пользовательские тексты — в конфиге/env,
  код знает только имена.
- Брендовые строки в коде = находка (названия/тексты владельца — из конфига).
- Новые зависимости: обоснование, зафиксированная версия, лицензия.

Severity: P0 — эксплуатируемо сейчас; P1 — риск при злоупотреблении;
P2 — гигиена/защита в глубину.
